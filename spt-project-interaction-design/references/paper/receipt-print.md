# 小票打印 · Receipt Print

## 适用场景

已经成功完成的专注记录、打卡、记账汇总或每日清单。小票是业务结果的展示和可选分享形式，不是实际纸质打印机，也不能代替后端保存成功。

## 数据与层级

先确认真实记录的数据源、成功状态和导出范围，再生成小票内容。日期、时长、数量、单位来自同一条记录；不把演示数值硬编码进真实项目，不凭动画结束新增记录。

先把整张小票排版完整，等待必要字体和图片就绪，再计算出口、纸张长度和运动距离。区分固定出票口、后方尚未露出的纸、前方出口遮挡边和已经露出的纸。

核心做法是完整纸张向下移动，出口遮住还没送出来的部分。文字一开始就存在，只是暂时不可见；不能用整体 scaleY 从零拉长纸张，也不能每露出一点就重新排版一次。

## 动作与状态

`等待真实记录 → 准备纸张 → 送出 → 短暂落稳 → 可保存`。

1. 记录仍在保存时显示真实保存状态，不先播放一张写着成功的小票；失败保留重试入口。
2. 送纸采用有限时长、带加减速的运动，出口位置保持稳定。纸边可有轻微弯曲、阴影变化，但数字和正文不跟着扭曲。
3. 送完后最多做短暂轻摆，然后稳定停住，不让用户一直追着文字看。
4. 完整小票稳定后再提供保存入口。重新播放时隐藏或禁用保存，完成后恢复；组件销毁或切换记录时停止旧动画。
5. 重播只重播呈现过程，不重复计时、不重复记账、不再次调用完成任务接口。

长小票按真实内容计算高度，在小屏提供滚动或完整查看方式；减少动态效果时跳过送纸和摆动，直接展示完整结果及保存入口。

## 保存必须是真的

优先沿用项目已有导出能力；没有时按目标平台选择可行方案。浏览器、原生 APP、小程序能力不同，先验证实际支持的图片生成、下载或相册授权流程，不直接照搬另一平台的接口。

- 导出的是完整小票，不是当前视口里被出票口裁切后的截图。
- 核对文本、日期、数字、插画、字体和长内容是否完整；字号和输出尺寸应足以阅读。
- 远程图片要确认加载与导出权限，处理跨域或字体不可用的问题；不为获取资产绕过权限。
- 导出时避免残留动画变换或临时按钮，可使用相同数据的独立静态导出视图，不能导出另一套过期数据。
- 点击保存后必须得到实际文件或平台规定的保存结果。仅触发下载时说“已发起下载”，没有确认落盘就不说“已保存到设备”。失败显示原因和重试入口。
- 包含个人信息时，让用户确认分享内容；不要自动上传、公开或发送给他人。

如果项目暂时不能导出，应明确交付缺口；不能用“保存成功”的假提示替代实际文件。

## 验收

- 真实业务请求失败时不会出现成功小票；成功记录的数字与原数据一致。
- 逐步查看送纸过程，出口固定、纸张逐渐露出，字形与行距从头到尾不变。
- 连续触发、重播、切换记录和离开页面不会重复写入数据或显示旧小票。
- 打印中不可保存半张票，完成后保存真实可用；导出的长小票不被视口或遮罩截断。
- 打开导出文件检查完整性和清晰度；只看到一个文件名不算验证通过。
- 小屏、长内容、图片加载失败和减少动态效果均有可用结果。
