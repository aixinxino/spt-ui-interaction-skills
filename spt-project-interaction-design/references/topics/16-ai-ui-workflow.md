# AI 整体 UI 设计流程

> 按需参考 · 主题 16《AI整体UI设计流程》。仅使用总入口选定的模式，不把本页全部效果加入项目。任务范围、输出形式与语言以用户当前请求和总入口为准。

先判断用户处在哪一步。已有页面优先检查与修正，不强制从零走完整流程；用户只要设计或概念图时，不提前编码或重构。开始实施前读取现有页面、组件、路由、样式和数据流，保留业务及无关改动。

## 1. 建立少量全局规则

从现有品牌、成熟组件或用户选定的参考中提取字体、字号层级、字重、颜色角色、间距、圆角、边框、阴影和内容宽度。给出可复用的变量与组件状态，不要求没有设计经验的用户逐个选择 8px 或 12px。

已有设计系统时沿用其默认值，只覆盖有依据的差异；不要另起第二套按钮、输入框和弹层。视觉规则应同时覆盖正常、悬停、聚焦、禁用和错误状态，而非只规定静态截图。少数主次明确的规则通常比大量孤立参数更容易保持一致。

UI 类 Skill 可以帮助建立和执行规范，但不承诺自动产生好看的页面。不要自动安装第三方 Skill，也不要用一份规范冒充经过选择的视觉方向。

## 2. 把结构讲清楚

列出主要页面、公共布局、导航关系和核心数据实体，区别“用户在哪里操作”和“代码怎么组织”。简单个人工具不默认引入微服务或复杂多层架构。

根据用户最常做的任务安排主工作区、辅助列表和操作入口。只问会改变页面安排的问题，例如偏阅读还是编辑、是否频繁跨内容切换；项目已经提供的信息直接读取。交付一份紧凑结构说明，不反复让用户确认同一批内容。

## 3. 功能必须包含状态

为关键操作列出输入、触发、处理中、成功、失败、取消及再次操作。新建、编辑、删除、搜索、保存等行为与真实数据和权限对应；没有后端时注明演示范围，不显示假成功。

设计空状态、长文本、较多条目和错误提示，不能只考虑首屏数据刚好填满的情况。功能变化需要更新对应页面与组件，不只改一张设计图。

## 4. 用概念图看方向

把统一内容和明确视觉参考交给有图片生成能力的工具，要求正视网页或应用截图，不附带电脑模型、摄影灯光或透视展示板。清楚区分文字设计方案、位图概念图和可编辑设计文件。

可先用相同内容尝试少量有明显差别的方向，选定后在原图上修改具体问题：保留什么、调整什么。不要每次只说“更高级”然后重新随机生成。

生成图只负责验证视觉方向，不能代替真实字体、排版、数据与交互测试。对重要文字、按钮和信息密度做可读性检查；别让主视觉把操作入口挤没。

## 5. 分块编码与对照

先实现全局变量、公共组件和一个代表性首屏，再展开其他页面。导航、标题、按钮、列表、表单都使用真实界面元素；插画与材质作为独立资产，不把整页图片铺底后盖透明按钮。

沿用项目现有技术栈和成熟组件。后台通常优先适配已有组件的主题、密度、字体和间距，不为换一种视觉风格重写整套选择器、表格、日期控件及弹窗。

在浏览器或对应平台逐块对照概念图，修正内容尺寸、留白、对齐和图片比例。窄屏重新安排层级，不整体缩小桌面版。不要以一次构建成功代替页面已经好用。

## 6. 资产与小细节收尾

把缺失的封面、插画、背景纹理等列为独立资产需求：用途、放置区域、宽高比、透明背景需求、主体留白、风格、光线与导出尺寸。使用用户已有资产规范或在获准生成后制作，并验证真实放置效果。

资产风格统一，但不让每个卡片都放一张装饰图。注意裁切、清晰度、加载占位与失败替代；文字和业务数据不要烘焙进资产。最后统一图标线宽、按钮状态、空页面和少量必要动效。

## 验收与交付

检查代表性桌面与手机布局、长文字、空状态、加载和失败、键盘焦点、关键功能及图片缺失。清楚区分概念图完成、代码完成、构建通过与实际运行验证。

交付全局规则、页面与功能范围、改动文件、资产清单和实际检查结果。未访问项目或未生成图片时明确说明，不宣称全部完成。
