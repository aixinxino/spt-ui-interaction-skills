# 三种触感交互

> 按需参考 · 主题 27《3种触感交互》。仅使用总入口选定的模式，不把本页全部效果加入项目。任务范围、输出形式与语言以用户当前请求和总入口为准。

先理解用户想完成的操作，再决定是否需要效果。保留现有产品和技术栈，不把项目改成视频里的演示页面，不强制三种效果同时出现。

## 1. 确认范围

- 用户只问适不适合、哪里能用或要求方案时，只给判断，不改代码。
- 用户要求实现时，检查目标页面、现有组件、状态与数据来源、样式规范、动画能力及目标平台，再实施最小必要改动。
- 用户已指定一种交互，优先实现这一种；只有存在实际冲突才说明调整理由。
- 缺少会改变实现的关键条件时，提出最少的问题，例如小票来自什么已完成记录、贴纸位置是否需要保存。可从代码确认的内容不重复追问。
- 没有项目访问权限时，提供适配说明或局部示例，明确没有完成项目集成，不声称已经实现。

## 3. 共用实现要求

### 保留项目风格与内容

沿用已有颜色、字体、圆角、组件和响应式规则。不要默认添加卡通角色、奶油色、SPT 品牌或虚构业务数据。用户明确要演示时可以使用标注为演示的数据。

插画、纸纹和材质可以使用独立图片；文字、按钮和动态数据使用真实界面元素。不要把整个界面做成一张图片，再盖透明点击区。没有合适资产时先用可替换的简单纹理或形状，不因此阻塞核心交互。

优先复用项目已有动画和绘制能力。Web 可以使用现有组件、CSS/SVG 等合适能力；原生 APP、小程序按其实际渲染与事件机制实现，不照搬 DOM 专用方案。不擅自新增大型依赖或重写页面。

### 动作跟随状态

把业务数据、交互状态和视觉进度分开管理。动画结束不能代替保存成功；打开、收起、取消和重新触发都必须有明确结果。

直接拖动时跟随输入，不用长时间缓动追赶手指。自动展开、收回和贴合时使用有加减速的短过渡，到位后停稳，留出阅读时间。避免整段匀速漂移、反复弹跳或无意义循环。不把某个固定时长或弹簧参数当成所有项目的标准。

再次操作时从当前可见状态接续或反向，不突然跳回起点；重复事件不能堆积多段动画或重复提交数据。取消事件、离开页面和组件销毁时清理监听与动画。

### 输入与可访问性

触摸、鼠标和键盘均有可完成任务的入口。点击操作使用有名称的真实按钮；拖动是主要功能时提供可用的非拖动替代方式。不要为装饰动画把整页滚动禁掉。

手势只绑定目标区域，处理移动阈值、捕获与取消，避免拖完又误触点击。界面缩放或容器变换后仍应使用一致坐标。

支持系统或项目的减少动态效果设置：保留业务结果和操作入口，省略大幅翻转、卷曲、长位移。可访问提示只在实际状态改变时更新，不逐帧播报。

### 性能与布局

避免逐帧重排整页；尽量让变化限制在当前组件内。拖动位置、裁切范围和阴影变化保持一致；复杂纸张形变只在确实需要且平台允许时增加。

检查手机小屏、长文字、图片未加载、窗口尺寸变化及低性能设备。可用时以稳定 60fps 为目标，但不能仅凭设置动画参数就声称达到 60fps；未测设备需注明。

## 4. 验证后交付

按选中参考文档中的验收项目，在真实页面操作从触发到稳定结果的完整过程。至少检查重复触发、反向或取消、手机滚动冲突、键盘操作和减少动态效果。只做静态截图不能证明交互正确。

小票保存等业务结果必须单独验证。工具或平台受限时，明确写出未验证项，并给出用户可以复现的检查步骤。

最后简要交付：选择了什么、用在哪里、改动文件、实际验证结果、尚未验证的设备或功能。不额外安装此 Skill，不自动发布页面、发送文件或提交代码。
