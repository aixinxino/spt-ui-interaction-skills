# 四种任务反馈交互

> 按需参考 · 主题 22《4种任务反馈交互》。仅使用总入口选定的模式，不把本页全部效果加入项目。任务范围、输出形式与语言以用户当前请求和总入口为准。

让用户知道完成了什么、正在等什么，以及下一步能做什么。反馈由真实任务驱动，动画只负责解释状态变化。

## 先核实任务契约

读取实际提交入口、接口、状态查询或推送、结果存储和页面状态管理。记录服务是否提供任务编号、阶段、可靠进度、取消确认、局部重试和去重能力。优先使用已有契约；缺少能力时明确限制，不能用前端计时器伪装后台进度。

区分页面当前任务、服务端任务标识、任务输入版本、结果项标识以及重试尝试。可以沿用等效的现有结构，不强制重写后端。仅有演示数据时标注模拟，不能宣称已验证真实取消或收费任务的重试。用户要求代码实现时完成相关链路，只做获授权的改动，不扩展为生产任务自动重跑。

## 1. 真实分阶段反馈

适合：任务有校验、处理、打包、上传等实际阶段。

实现：
- 由服务事件或查询结果更新已完成、当前、未开始和失败阶段；完成一项打勾，再突出实际正在执行的阶段。
- 只有数据可信、分母有定义时展示百分比；否则显示阶段和“处理中”，不自动跑到99%。
- 处理乱序或晚到状态，终态不得被旧处理中事件覆盖；有服务版本号或序号时用其判断新旧。
- 状态文字与图标共同表达，不只靠颜色；向辅助技术播报有意义的阶段变化，不逐帧播报。

直接指令：
> 为这个任务展示真实阶段，完成一项打勾，突出当前正在执行的步骤。有准确数据才显示百分比，否则显示阶段；不要用计时器假装进度，处理乱序状态与最终失败信息。

验收：人为延迟某阶段时界面确实停在那里；失败显示在对应阶段；旧事件不能让完成任务倒退。

## 2. 结果逐步可用

适合：结果可分项独立使用，无需等待全部完成。

实现：
- 以稳定结果项标识显示占位、处理中、可用、失败状态；完整且可使用的项先开放预览、下载或后续操作。
- “已有部分字节”不等于文件完成；流式文本的草稿与最终结果也应区分。
- 预留合理空间，局部占位平滑替换为结果，不把用户当前阅读位置顶走。
- 一项失败不抹掉其他已完成项；当前项状态或数据更新时保留用户焦点和选择。

直接指令：
> 已经完成且可独立使用的结果先开放预览和操作，其余继续处理。按稳定标识更新对应项，预留布局空间；不要等所有任务结束再一次铺满，也不要提前开放未完成文件。

验收：第一项完成即可使用，其他项仍显示真实状态；结果顺序变化不串项；出现新内容不明显挤动阅读位置。

## 3. 中途修改隔离旧结果

适合：用户换条件、取消后重开、连续生成或快速切换对象。

实现：
- 每次逻辑任务有独立身份与输入版本；响应只有匹配当前任务及相关对象时才可写入当前界面。
- 请求取消和结果隔离分别处理。即使中止浏览器请求，后台仍可能继续执行，晚回来的旧结果也必须被拦截。
- 支持取消时先显示“正在请求取消”，收到确认才显示已取消；失败、暂不支持或无法确认时如实说明。
- 新任务不受旧任务回调、重试结果、进度事件或错误提示覆盖。旧结果若保留到历史，应明确归属于旧任务。

直接指令：
> 给每次任务独立编号并关联输入版本，晚回来的旧结果不能覆盖新任务。取消需要服务确认；停止转圈不等于后台停止，不支持或无法确认时显示真实说明，同时隔离所有过期响应。

验收：让任务A延迟，启动B并先完成，再返回A；页面仍是B。取消请求失败时不得显示已取消。

## 4. 失败后局部继续处理

适合：批量任务中只有部分失败，已成功部分仍然有效。

实现：
- 保留已完成项，只在失败项展示具体原因和重试入口；重试时仅更新对应项。
- 成功项是否可复用要检查输入和依赖版本。相关条件改变后使受影响结果失效，不能盲目复用。
- 对重复点击和重复请求建立去重或幂等边界，沿用服务约定；区分同一尝试重发与用户明确发起的新尝试。
- 请求超时表示客户端未拿到结论，不自动等同失败。能查状态先查；无法确认时显示“状态待确认”等明确说明，不自动重提可能收费或有副作用的任务。
- 自动查询或重试需有次数、时间或退避上限以及停止条件，不能无限循环；非幂等操作在状态不明时保留给用户决定下一步。

直接指令：
> 只重试失败的部分，保留仍适用于当前输入的成功结果，并在原位置更新。条件变化后重新处理受影响项。超时先查询任务状态，无法确认就提示，不自动重复提交可能产生费用的任务。

验收：部分失败时成功项仍可用；重复点击不会重复提交；输入改变后旧成功项不被误用；模拟超时不会自动启动第二笔任务。

## 状态设计与交付

提交、运行、取消请求中、已取消、成功、部分失败、失败和未知状态按服务实际能力建模；不要硬加服务不支持的假状态。刷新后需要继续跟踪时，用已有任务查询能力恢复；不支持恢复就说明边界。

使用可控的延迟、乱序、局部失败、超时和取消拒绝场景验证状态机及页面，演示测试和真实接口检查分开记录。不要为验证制造生产费用或修改生产数据。交付接口边界、修改位置、任务身份策略、取消与重试规则，以及实际运行过的检查。
