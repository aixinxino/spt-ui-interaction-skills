# 从参考图到可实现的界面

> 按需参考 · 主题 18《概念图到代码》。仅使用总入口选定的模式，不把本页全部效果加入项目。任务范围、输出形式与语言以用户当前请求和总入口为准。

先确认用户要参考分析、生成图片还是实现代码。用户未要求开发时不要提前写项目。已有需求和页面结构直接使用，不重复进行漫长的功能访谈；只补会影响画面或实现的缺失信息。

## 1. 把参考拆成能描述的东西

请用户提供喜欢的截图或可读取页面，区分喜欢的是排版、留白、配色、主视觉、材质还是动效。说不出风格名称时先看实例，不要求背术语；可以使用用户自己的风格资料库或提供的例图。

提取可迁移特点，不复制对方品牌、内容、插画和完整布局。不把设备模型、摄影灯光、斜透视展示板带来的高级感误认为网页本身的质量。未真正读取链接内容就不要声称已分析。

给 AI 的参考分析请求：

> 分析这张参考图：哪些特点来自排版，哪些来自图片或材质？用大白话说明我能借鉴的三四个要点，并区分普通组件能实现的部分与需要独立资产的部分。先不要生成图片，也不要写代码。

## 2. 分开生成方向，不拼成一张设计墙

使用同一份真实文案和功能入口，尝试有明显表达差别的方向。创意网站可比较编辑式排版、桌面隐喻、数字展厅；这是可选示例，不是每个项目都必须用的三个模板。

每个方向单独出一张正视首页概念图。固定画布比例和必需内容，避免只是给同一组圆角卡片换颜色。用户选中后才继续该方向，不自动无限生成。

生成图片的请求模板：

> 请直接生成【桌面或手机尺寸】的网页首页概念图，不只回复文字，也不要写代码。使用附件里的真实文案与内容清单，保留【必需入口】。参考图只借鉴【具体视觉特点】，不复制原品牌和作品。画面是正对屏幕的网页截图，不要电脑模型、斜透视或外部摄影布景。标题、正文、按钮应清楚，布局能由普通网页组件与独立主视觉资产组合实现。

明确将提示词交给支持图片生成的工具；没有生成能力时交付提示词并说明限制，不把文字方案称为已经生成的图。

## 3. 后台走组件主题路线

后台优先沿用成熟组件，不为视觉变化自己重做表格、日期选择器、弹窗与表单验证。检查项目已采用的组件库与主题能力；未选型时先结合框架和使用要求给出少量候选，不擅自安装。

通过颜色角色、字体、密度、圆角、边框、留白、侧栏宽度和图表样式建立区别。可试白灰简洁、暖白墨绿、浅灰低饱和强调色等方向，但应由参考与品牌决定，不默认蓝紫渐变或大圆角堆卡。

后台概念图请求：

> 为附件中的后台页面生成正视概念图。保留现有导航、筛选、表格或列表和操作入口，按【参考风格】调整色彩、字体层级、信息密度与留白。使用能用成熟组件主题适配的结构，数据保持真实意义，避免用巨大插画或装饰卡片替代实际业务内容。

## 4. 锁住满意的地方再迭代

把选定图重新作为参考，每轮指出少数具体变化，例如主视觉缩小、标题不遮挡、按钮更明显、项目用途可读。写明保持配色、主体、材质、构图中的哪些部分不变，保留各轮结果以便回退。

判断是不是海报而不是界面：正文能读吗，主要操作能找到吗，数据更多时能容纳吗？这些是落地检查，不要求用户先成为设计师。

## 5. 把图片拆成实现计划

列出三个清单：代码组件、独立资产、需要额外能力的效果。

- 导航、文字、按钮、卡片、表格和表单使用真实组件。
- 复杂雕塑、插画、纹理单独生成或使用获准资产，保留主体形状、材质和光线，去除文字和按钮。
- 简单背景、分隔、边框和轻量装饰优先用代码。
- 图片轻浮动或小幅视差不等于真正三维；若需要转到背面或动态反射，检查是否有可用模型、分层素材或序列帧，不承诺单张普通图片能还原隐藏结构。

独立资产请求：

> 以选定概念图为参考，只生成其中的【主体资产】，保持形状、视角、材质和光线。不要文字、按钮和整页背景。按放置需要使用透明背景或明确的独立背景，预留合适边距，导出比例为【目标比例】。

手机概念图沿用同一视觉方向，但重排内容与操作，不把桌面全页缩小。生成图中文字如不准确，以真实文案为准。

## 6. 实现并对照真实页面

用户要求编码后，再把定稿、资产和真实文案交给项目实现。先做代表性首屏，检查文字装得下、主视觉不挡按钮、手机不溢出，必要时回调布局。

交付参考特点、选定方向、可复制提示词、资产需求、组件与实现边界，以及实际生成或运行的结果。没有生成、没有开发、没有测试的部分分别标注；概念图通过不等于开发已验证。
